# Agents assistance lifecycle and reliability

World Run creation and copying have no Agents side effects. Assistance is an explicit Agents-owned lifecycle reached through discoverable Workspace Capabilities. Workspace assistance and Run-family assistance use ordinary revisioned Room Definitions; creation is serialized per target, persisted before success, and reuses the oldest matching Room. A failure while creating membership rolls back the Room and its spawned AI. Definition-created AI profiles carry only their owning Room id, never World Resource ids, and are removed with that Room.

Run Rooms persist a generic Subject Selection. The default `all except []` family selection picks up future copies from World's live derived catalog. A fixed `selected only` selection stays fixed. Optimistic scope revisions prevent two browser edits silently overwriting one another. The capability broker accepts both `contains` and `member-of` catalog directions, requires full Resource identity, and checks read/write grants at each call. Destructive commands are never covered by a semantic Room-subject grant.

The embedded Agents UI receives a focused Room URL, filters its authoritative snapshot to that Room and its members, and starts with the left rail collapsed. The Host rejects a World/Room URL combination when the Room does not select the Run. Hiding and reopening the Agent pane preserves server-side conversation state. Room creation, Run copying, dynamic family resolution, subset exclusion, concurrent assistance opening, runtime eviction/restore, failed membership rollback, Room-owned Agent cleanup, and real Host → Agents → World invocation are regression-tested.
