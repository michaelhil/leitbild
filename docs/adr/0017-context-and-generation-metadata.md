# Preserve useful context and keep generation metadata out of conversation text

Agent requests retain stable instructions and exact recent conversation while large operational evidence is fetched on demand through focused discovery. Native tool calls and tool results remain structured provider messages, structured results use compact JSON, and prompt budgets are derived from the effective model and actual tool surface. Cache and generation measurements are stored as Message metadata and rendered by Clients, never appended to response text.

Every generated response also references a separately stored, complete provider-independent generation query: model settings, system instructions, conversation messages, native tool calls and results, tool schemas, images, and provider cache blocks exactly as supplied to the final model call. The query is fetched only when a user opens the response's inspection icon; it is not embedded in ordinary Room reads and never becomes future model context. The inspector derives navigable prompt categories and paired tool interactions from that exact request without creating a second audit representation. Credentials, provider-side hidden instructions, SDK wire transformations, and transport headers are outside this request shape and the UI says so explicitly. Deleting a message or Room deletes its query. This makes behavior inspectable without turning observability into prompt or network bloat.

Product-source citations remain ordinary response text rather than persisted citation objects. The universal message renderer recognizes only allowlisted deployed-product paths, condenses them to source-link icons, and loads the referenced file on demand in a modal. This keeps citations useful and compact without introducing an Agent-specific response protocol or exposing operational files.

We rejected automatic lossy history compression, result-answer caches, rigid discovery sequences, and arbitrary retrieval quotas because each can silently remove, stale, or prevent relevant evidence.
