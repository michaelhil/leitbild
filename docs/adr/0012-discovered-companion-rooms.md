# Companion conversations are discovered, not Workspace defaults

Opening a Simulation Run in the Host ensures a companion Room through an explicitly advertised Definition Capability. An ordinary, editable Agents Room Definition declares the Resource type it accompanies; no World template names, Pack IDs, Agent IDs or model names are embedded in the Host. The Agents-owned Room persists a `companionOf` Resource reference and publishes it as a `companion-of` link. Creation is serialized per Resource within the Workspace runtime, persisted before success, and reuses an existing association across reloads and Definition edits. Missing or ambiguous Definitions produce a visible, retryable error while World remains available.

The association is context, not a permission grant or continuous Binding. The Workspace broker exposes the current Room's links without adding Resource IDs to Agent configuration. The bundled assistant has read-only grants and ordinary editable persona/model settings. Removing a Run does not delete its conversation; removing a Room permits a new companion on the next open. Workspace provisioning remains identity-only and lazy. We accept that opening a Run can create a Room and AI Profile, rather than showing an empty Agents pane that looks broken. No cross-Module transaction or universal workflow runtime is introduced.
