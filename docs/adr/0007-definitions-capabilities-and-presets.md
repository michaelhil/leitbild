# Definitions, Resources, Capabilities, and Presets form the orchestration model

Leitbild uses Module-owned Definitions to describe what can be created, Resources for live state, and typed Capabilities for every meaningful external operation. Reusable fragments remain inside one Module and compile into normalized Definition Revisions. Cross-Module Presets reference stable Definition IDs through independent, apply-once Capability calls and create ordinary Resources without embedding Module-private payloads or becoming an ongoing workflow controller. Created World runs pin their resolved Scenario Revision; an Agents Room Definition is fully instantiated into ordinary room and agent state. Ongoing automation remains owned by World Timelines or Agent Scripts. No generic cross-Module relationship runtime exists; a concrete continuous behavior must justify and own its own typed implementation.

Presets deliberately have no step-output references, branches, schedules, rollback fiction, or runtime state. Independent actions run together and each outcome is reported; a partial result remains visible and operable. If editable Agents Definitions are introduced later, they must gain immutable revisions before Presets may reference them.

This rejects both a universal scenario tree/runtime and unrelated browser-side launch procedures. A universal engine would couple the Host to every Pack and confuse simulation time, continuous physics, wall-clock schedules, and multi-Agent turn-taking, while browser procedures are not durable, discoverable, or AI-invocable.
