# Run clock and observation time

Each Run owns one monotonic clock, supplied as a read-only clock to every local Pack. Standalone Pack hosts can own their own clock; Packs inside a Run do not create independent anchors. Wall time labels observations, accepted events, health, leases and external Agent work. Physics, local curves, scenario cues and recording cadence use simulation time. Historian samples already carry both observation and simulation time; internal solver elapsed time is a local integration coordinate, not another Run clock.

Unloaded time does not advance a simulation. Restore reanchors saved simulation progress at the current wall time. Changing the epoch of existing live state is not time travel: public clock controls therefore only change pause/speed. Genuine seek would require restoring and advancing *all* state, including fired cues, procedure state and every Pack; no Pack may pretend to support it by relabeling timestamps.

Pack solvers retain their numerical steps and update cadence, but derive elapsed work from the shared clock semantics rather than assuming a timer fired on schedule. Queries remain read-only. Clock transition work must retain elapsed progress under the old speed before adopting the new speed. Shared object/event timestamps are observation time; Pack-owned samples and physical projections explicitly identify simulation time. Neither wall-clock corrections nor UI interpolation drive physics.

Clock controls are serialized. The Run freezes its clock at a synchronization boundary, validates and flushes Pack progress, then publishes the new rate/pause state. Failed validation resumes the original rate; a partial application failure leaves the shared clock frozen and the Run paused. Shutdown freezes and flushes before unsubscribing or saving its final snapshot; restarting does not integrate time spent offline. Recording cadence uses Run elapsed time, not the youngest Plant or Grid's private age.

Timeline execution is serial, ordered by due time and then authored order, with one pending wakeup. Started cues are retained and not replayed after restore; a failed cue reports an error instead of retrying partially executed actions. Drone integration retains bounded-step backlog instead of discarding elapsed time, reports lag in runtime health, and drains it at clock synchronization boundaries.

This is not a new transaction manager: abrupt process/storage failure still is not crash-atomic across the event journal, shared snapshot and private Pack checkpoints (ADR 0029). Unreadable or inconsistent retained state must fail visibly, never be silently reinitialized or relabeled as current. A future exact seek or crash-replay feature needs coordinated state generations, not another clock or a timestamp override.
