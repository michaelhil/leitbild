# Complementary inspection-part cost census

This diagnostic tests a proposed ownership-preparation shortcut, not a production change or a timing result. It runs the current baseline eligibility and partition code without skipping any pair, against the admitted R5 unit and campus with every declared mesh layer requested.

The camera selector chooses exactly one `full` or `cut` inspection part for each occurrence. Two opposite, defined parts of the same occurrence therefore cannot coexist. This proof does not extend to all faces of one object or to different objects with different parts.

The [receipt](inspection-part-census.json) records successive baseline predicates. For the unit, complementary parts account for 43,090 of 3,946,353 earlier leaf candidates (1.09%) and 9,249 of 183,625 coplanar candidates (5.04%). The campus has no such pairs. Positive overlap applications are recorded separately; their count is not a saved-time estimate or the count of visible output triangles.

These counts do not establish a material cold-loading gain. The geometry-changing exclusion remains unimplemented. Any future candidate needs measured phase costs and selected surface/material/normal/area, actual raster and pick equivalence, including fractional opacity and contact with third objects. Raw prepared byte equality would not be expected if a partition is removed.

Reproduce from `apps/world`:

```sh
LEITBILD_INSPECTION_CENSUS_RECEIPT=/tmp/inspection-part-census.json bun scripts/physical-layout/inspection-part-census.ts
```

The script instruments a temporary copy of the exact ownership module through guarded unique markers, records its original SHA-256, and removes the temporary file afterward. Instrumentation changes counters only. It does not rewrite a retained source, compiled Design, production algorithm or solver.
